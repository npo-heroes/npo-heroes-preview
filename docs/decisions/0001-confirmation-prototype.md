# 0001: Figma確認用サイトの実装方針

- 決定日: 2026-10-09
- 状態: 承認済み
- 対象: `npo-heroes/npo-heroes-preview`

2026-10-10追記: 決定6・7の案内表示は[0002](0002-review-interactions.md)で変更した。以下は当初の決定として保持する。

## 背景

スポンサーを含む関係者が、Figmaのレイアウト・ロゴの大きさ・画面遷移をブラウザで確認できるようにする。単一HTMLのトップページを、8ページを持つ確認用サイトへ拡張する。本番WordPressとは別に運用する。

## 決定

1. Vite、TypeScript、共通HTMLテンプレートによる静的な複数ページ構成(MPA)とする。各パスに`index.html`を生成し、GitHub Pagesで直接アクセス・再読み込みできるようにする。SPAのルーティングやサーバーは導入しない。
2. デザインの正本は指定されたFigma。トップは`597:5140`とし、旧版`77:2849`は使用しない。
3. PC・スマートフォンのFigmaを基準に、幅に応じて自然に折り返すレスポンシブ実装とする。ページ全体を画像化したり、固定キャンバスを縮小して配信したりしない。
4. 見た目、ページ遷移、メニュー、ページ内操作の確認を対象とする。送信処理・決済・本番CMS連携は実装しない。
5. ニュースの文章・画像・日付はFigmaに固定する。新しい本番記事への自動差し替えはしない。
6. 詳細デザインがあるニュース1件のみ詳細ページを作る。他の記事は確認用の案内を表示し、本文を創作したり本番記事へ誘導したりしない。
7. お問い合わせはFigmaのメールアドレス表示を再現する。フォームは追加しない。寄付など実処理が必要な導線は確認用の案内を表示する。
8. 大樹生命ロゴは`https://www.taiju-life.co.jp`を別タブで開く。
9. `main`にソースを管理し、GitHub Actionsで検証・ビルド・Pages公開する。従来の`gh-pages`履歴は復旧用に残す。
10. 設計、意思決定、検証・公開手順はサイトから独立した`docs/`へ保存する。決定変更時は新しい連番の記録を追加し、過去の判断を追跡可能にする。

## 比較した案

- 単一HTML継続: 共通部分・画像・複数ページの保守が難しくなるため不採用。
- SPA: 静的な確認サイトには不要で、Pagesの直接アクセスに追加対処が必要になるため不採用。
- 本番記事へのリンク: 閲覧者が確認サイトから離れ、デザイン未提供の記事を混同するため不採用。
